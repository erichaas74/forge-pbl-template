# Live Strategy League — minimal practice prototype

Open `/projects/live-strategy-league` from the project catalog. Run `npm start` for local development.

This first version implements the build spec's local-prototype stages: five demo teams, four timed rounds, three numeric decisions, cash/units sold/profit, changing conditions, locking, separate calculation and reveal, final standings, and personal round history. The learner controls Nova; four deterministic simulated teams submit when Nova locks or the round closes. No random draws are used.

Open round → enter decisions → lock → calculate → reveal → next round. The final reveal names a winner. Teacher controls pause, resume, extend, or close the timer. Closing uses the last valid saved decision; an unaffordable saved decision is replaced with a feasible simulated decision. Prediction and reasoning are optional and are preserved in history. Ties use stable team ID ordering. Scores are not grades.

The next round starts with your previous choices so you can revise your strategy. After the final reveal, expand “Start another practice” to explicitly replace the saved run and play again.

Valid form changes save on blur. The browser adapter persists snapshots under tenant/class/project/version/actor/attempt scope, with a revision check to catch stale tabs. Timers use an absolute deadline and catch up after reload. Calculations are deterministic and may run only once per round; standings change only on reveal. Persistence errors are shown rather than silently treated as saved.

## Reuse and boundaries

`public/projects/live-strategy-league/project.json` owns the theme, decisions, metrics, teams, round duration and world conditions. The framework-independent engine handles state transitions. Registered `market-v1` and `resource-v1` models own subject calculations; the resource-management fixture proves a second theme against the same engine. Unknown models fail explicitly. The Angular shell renders config and state through one scoped service and a persistence interface.

Existing catalog, project host, lazy launcher registry, single-config package runtime and session context are reused. No core contracts changed. The new template is registered as `live-strategy-league@1.0` with schema `1.0`.

This is **local practice**, not an official classroom competition. Browser state and preview teacher controls are not an authorization boundary. The launcher rejects server-authoritative sessions. Backend/team membership/realtime adapters, full 60-minute championship orchestration, role lessons, abilities, grading, awards and replay animation are deferred. These are deliberately outside the user's minimum first build.

The leaderboard has an optional root-relative `teams[].imageUrl` for group portraits, falling back to the team initial when absent. Demo photos are generated fictional groups; see `TEAM_PORTRAITS.md` for prompts and asset paths. The first revealed ranking shows NEW. From the second reveal, arrows compare current and previous rank, with text labels and a biggest-climber callout. The leading row receives a gold treatment; pending calculations never enter the leaderboard. Row movement and score flashes respect reduced-motion preferences. Presentation uses the same saved scores and history; no new scoring rules or persistence format were introduced.
